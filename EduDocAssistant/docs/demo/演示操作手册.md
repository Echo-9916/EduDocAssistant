# 演示操作手册（点击级）

> 适用：2026-11-13 版课堂演示。所有按钮、菜单、提示均取自当前前端源码；页面文案找不到原文的标「待确认」。
> 演示主线六步（发布 → 看到 → 提交 → 批改 → 分数评语 → 消息）全部写库；协作页为 mock，单独标注。

## 一、准备工作

### 1. 启动顺序

| 顺序 | 服务           | 启动命令                                                                                              | 端口        | 成功判断                                                                                                                                                        |
| ---- | -------------- | ----------------------------------------------------------------------------------------------------- | ----------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1    | Oracle / Redis | `docker ps`，确认 `oracle-dev`、`redis-dev` 在运行；未起时先启动这两个容器                      | 1521 / 6379 | 两个容器状态为 `Up`                                                                                                                                           |
| 2    | ai-service     | `cd EduDocAssistant/ai-service` → `.venv/Scripts/python.exe -m uvicorn app.main:app --port 8000` | 8000        | 浏览器开 `http://127.0.0.1:8000/health`，返回 `"status":"UP"`                                                                                               |
| 3    | backend        | `cd EduDocAssistant/backend` → `mvn spring-boot:run`                                             | 8080        | 日志出现 `Started EduDocApplication in ... seconds`，且出现 `信箱投递 worker 已启动：stream=edudoc:stream:notification group=cg-notification concurrency=1` |
| 4    | web            | `cd EduDocAssistant/web` → `pnpm dev`                                                            | 5173        | 终端出现 `Local: http://localhost:5173/`，浏览器能打开登录页                                                                                                  |

- 若后端连不上库，按 `application.yml` 的默认值或环境变量 `EDUDOC_DB_USERNAME` / `EDUDOC_DB_PASSWORD` 调整（默认 `user_cidas` / `cidas123`）。
- 本机没有 `sqlplus`，数据库检查统一进容器：`docker exec -it oracle-dev sqlplus user_cidas/cidas123@//localhost:1521/FREEPDB1`。

| 窗口               | 用途   | 登录账号                        | 密码          |
| ------------------ | ------ | ------------------------------- | ------------- |
| 普通窗口           | 教师端 | `teacher`（显示名「李老师」） | `Cidas@123` |

### 3. 从空状态补齐演示数据

刚跑过种子的库通常只有账号、2 门课程和 2 份作业；**模板与文档为空**。先对照空状态，再决定补什么：

| 页面 | 空状态长什么样 | 要不要补 |
| --- | --- | --- |
| 学生「我的文档」 | 表格「暂无数据」 | 必须补 1 份「就绪」文档（3.4） |
| 学生「课程与作业」 | 「我的作业 0」，表格「暂无数据」 | 不用补，主线第 4 步发布后出现 |
| 学生「消息通知」 | 表格「暂无数据」 | 不用补，演示中会产生 |
| 教师「作业与提交统计」 | 表格「暂无数据」 | 不用补，主线第 4 步现场发布 |
| 教师「课程管理」 | 正常情况下有 2 门种子课；若一行都没有 | 先建课（3.1），再处理学生入课（3.2） |
| 教师「课程模板」 | 表格「暂无数据」 | 主线不需要；要加演模板再补（3.3） |
| 学生「格式与模板」 | 「课程尚未发布模板」 | 教师发布模板后自动出现，不是故障 |

#### 3.1 若教师端没有课程：新建课程

| 操作 | 位置 / 原文 | 输入 / 结果 |
| --- | --- | --- |
| 1 | 教师窗口 → 左侧「课程与作业」→ Tab「课程管理」 | 打开课程列表 |
| 2 | 点右上「新建课程」 | 弹窗标题「新建课程」 |
| 3 | 「课程名称」「课程代码」「学期」 | 例如 `Web开发技术`、`CS101`、`2026-2027 秋`；学期只能从下拉里选 |
| 4 | 「默认文档权限」 | 保持默认「可评论」；这是演示字段，后端创建接口暂不接收 |
| 5 | 点「创建课程」 | 提示 `课程《Web开发技术》已创建，可通过「成员导入」添加学生`；列表新增一行，状态「进行中」 |

- 新建课程会自动把创建者（教师）记成课程成员；教师自己能看到这门课。
- **新课里没有学生**。下一步必须把 `student` 加进去，否则学生看不到作业。

#### 3.2 把 student 加入课程（界面无法完成，需 SQL）

「成员导入」弹窗里的预览行是固定的 `2023001 张同学 / 2023002 陈同学 / 2023003 刘同学`，后端按 `accountNo` 匹配 `edudoc_user.username`。`student` 的 username 不是 `2023001`，所以**通过界面导入不会把 `student` 加进课程**，只会新建/激活 2023001 等账号。

- 用种子课程（Web开发技术 CS101 / 2026-FALL）时，`student` 已经是成员，跳过本步。
- 用 3.1 新建的课程时，在 `oracle-dev` 容器里执行（把课程代码/学期换成列表里看到的值）：

```sql
INSERT INTO edudoc_course_member (course_id, user_id, member_role, group_name, status)
SELECT c.id, u.id, 'STUDENT', '演示组', 'A'
  FROM edudoc_course c, edudoc_user u
 WHERE c.course_code = 'CS101'
   AND c.term_code = '2026-2027 秋'
   AND u.username = 'student'
   AND NOT EXISTS (SELECT 1 FROM edudoc_course_member m
                    WHERE m.course_id = c.id AND m.user_id = u.id);
COMMIT;
```

#### 3.3 若教师端课程模板为空（可选，主线不需要）

只有要演示「发布模板 → 学生端同步」时才做，约 1 分钟：

| 操作 | 位置 / 原文 | 输入 / 结果 |
| --- | --- | --- |
| 1 | 教师 → 左侧「课程模板」→「新建模板」 | 弹窗标题「新建模板」 |
| 2 | 「选择课程」+ 模板名称 | 选 `Web开发技术`；名称填 `Web开发技术课程设计报告模板` |
| 3 | 点「确定」 | 提示 `草稿已创建，请上传 .docx 模板文件解析规则`；列表出现「草稿」 |
| 4 | 该行点「编辑」→「上传 .docx 并预览解析结果」 | 选一份 `.docx` 模板；成功提示 `解析出 N 条规则，确认后才会生成新版本` |
| 5 | 点「确认保存为新版本」 | 提示 `新版本 v1 已生成`；版本选择框出现 `v1 可发布` |
| 6 | 点「发布确认」→「确认发布」 | 提示 `已发布，学生端同步最新版本`；列表状态变「已发布」 |
| 7 | 学生 →「格式与模板」 | 不再显示「课程尚未发布模板」 |

没有模板文件时，第 4 步解析不出规则，可点「添加规则」逐条添加；演示时间紧就不做模板。

#### 3.4 学生上传一份「就绪」文档

| 操作 | 位置 / 原文 | 输入 / 结果 |
| --- | --- | --- |
| 1 | 学生窗口 → 左侧「我的文档」 | 打开文档列表 |
| 2 | 点右上「上传文档」 | 弹窗标题「上传文档」 |
| 3 | 拖入或选择 `.docx` / `.doc` / `.pdf` | 单文件不超过 20MB；弹窗内文字「拖放文件到这里，或从本地选择」 |
| 4 | 「文档标题」输入框 | 保持文件名自动生成的标题即可，例如 `Web开发课程设计报告_张同学` |
| 5 | 「选择课程（可选）」 | 选学生已加入的课程，种子为「Web开发技术」 |
| 6 | 「文档类型」 | 选「作业」或「报告」 |
| 7 | 点「开始上传」 | 弹窗自动关闭，列表新增一行 |
| 8 | 等待状态标签 | 「解析中」→「就绪」；只有「就绪」才能预览和提交 |

上传依赖 OSS 配置；若报上传失败，先检查后端 OSS 环境变量与 Bucket CORS，不要在现场反复重试。

### 4. 演示前检查清单

- [ ] 后端日志有 `Started EduDocApplication` 和 `信箱投递 worker 已启动`。
- [ ] 学生「我的文档」里至少有一行状态为「就绪」。
- [ ] 教师「课程管理」至少有一行课程；学生已加入该课程（学生端课程筛选里能看到，或查 `edudoc_course_member`）。
- [ ] 要演示模板时，教师「课程模板」至少有一行状态「已发布」；不演示可忽略。
- [ ] 教师左侧有「课程与作业」菜单；学生左侧有「课程与作业」「消息通知」菜单（缺菜单通常是权限点未导入）。
- [ ] 学生「消息通知」未读数为 0，或已知未读来源；避免演示时把旧消息当新消息。
- [ ] 两个窗口都已登录并停在首页，演示开始后不再登录/登出。

数据库侧核对（在 `oracle-dev` 容器内执行）：

```sql
SELECT username, display_name, account_status FROM edudoc_user
 WHERE username IN ('student','teacher','ops');          -- 期望 3 行，均 A
SELECT COUNT(*) FROM edudoc_course WHERE term_code = '2026-FALL'; -- 种子 2 门；新建课程则 ≥ 1
SELECT COUNT(*) FROM edudoc_course_member
 WHERE user_id = (SELECT id FROM edudoc_user WHERE username='student')
   AND status = 'A';                                       -- 期望 ≥ 1
SELECT title, status FROM edudoc_assignment;               -- 有种子则为 1 PUBLISHED + 1 DRAFT；无也不影响
SELECT COUNT(*) FROM edudoc_document
 WHERE owner_id = (SELECT id FROM edudoc_user WHERE username='student')
   AND status = 'READY';                                   -- 期望 ≥ 1
```

### 当前无法操作 / 可点但不写库

- **主线六步全部可操作**；前提是学生已加入课程且有「就绪」文档（见一.3）。
- **通过界面把 `student` 加入新建课程：当前无法操作**。成员导入弹窗发送的是固定预览行（`2023001` 等），后端按 `username` 匹配，不会命中 `student`；必须用 3.2 的 SQL，或直接用种子课程。
- **新建模板必须先有 `.docx` 模板文件**：没有文件时解析不出规则，只能手工「添加规则」；主线不需要模板。
- **「提醒未提交学生」不能真正投递**：按钮和名单都能打开，但只生成名单、不发送消息；界面已写明「提醒投递随消息切片开放」。
- **个人中心「下线」其他会话一定失败**：点后后端回 40901，会话列表不会删行；当前只支持令牌自然过期。
- **批量下载提交文档 / 导出统计表格**：界面没有入口，当前无法操作（需求有、后端未实现）。
- **实时协同（在线光标、并发合并）**：没有入口，当前无法操作；协作页只有 mock 批注/版本/共享。
- **协作页的共享设置、协作者增删、批注、版本恢复**：可以点，但只改浏览器内存，**刷新即回种子态，不写库**。
- **审计页「冻结账号」**：可以点，但只改 mock 数组，不会出现在真实操作日志里。

## 四、一键恢复

没有现成的「重置演示」按钮。推荐按下面顺序恢复：

1. **最稳**：演示前对演示库做一次快照（Oracle Data Pump 或容器卷备份），演示后整库恢复。首次使用前先在测试库演练一次恢复命令。
2. **只清演示产生的数据**（仅演示库执行；执行前先备份，首次使用前在测试库验证）：

```sql
-- 1) 清空站内消息（种子没有消息行）
DELETE FROM edudoc_notification;

-- 2) 清掉演示提交触发的未投递事件，避免恢复后 Worker 又补发
DELETE FROM edudoc_outbox_event
 WHERE aggregate_type = 'SUBMISSION'
   AND status IN ('NEW', 'FAILED');

-- 3) 删除演示现场发布的作业及其提交，保留两条种子作业
DELETE FROM edudoc_submission
 WHERE assignment_id IN (
   SELECT id FROM edudoc_assignment
    WHERE title NOT IN ('Web开发课程设计报告', '索引设计实验'));
DELETE FROM edudoc_assignment
 WHERE title NOT IN ('Web开发课程设计报告', '索引设计实验');

COMMIT;
```

> 上面这段只清理「种子课程上的现场作业/提交/消息」，**不会删除 3.1 新建的课程或 3.3 新建的模板**。从空库开始演示时，请用第 1 条的快照恢复，别用这段 SQL。

3. **前端状态复位**：协作页刷新即回种子；摘要任务若想重来，点「重新生成摘要」，或在浏览器开发者工具 → Application → Local Storage 删除本站的 AI 任务键（换一个全新的隐身窗口也会得到干净状态）。
4. **不要删的**：学生那份「就绪」文档、三个种子账号，以及你选择使用的课程/入课关系/模板（种子课程或 3.1–3.3 新建的）；删了就要重新走一遍 3.1–3.4。种子作业「Web开发课程设计报告」「索引设计实验」可保留，主线不依赖它们。
