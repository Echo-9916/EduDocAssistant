# 01 fullstack-auth 垂直切片 · 登录

> 状态取值：`未开始` / `进行中` / `已完成`（本阶段新建，全部 `未开始`）。
> 范围：本地（LOCAL）账号登录闭环 + 服务端令牌撤销；student/teacher/ops 三角色 + 账号受限态；找回密码、权限申请前端按原型做、后端只留占位接口。
> 契约源：《详细设计说明书》§2.2/§2.3/§2.5/§4.1/§4.4/§5.1、《概要设计说明书》§5.2 I01/§7.1、《数据库设计说明书》§3.4.1–§3.4.5、`04_登录与认证页面设计规范.md`、`06_三角色路线与交互边界.md`、`04_seed.sql`。

## A-01 数据库迁移 · 认证种子账号（db_seed 启动执行）

- **需求/设计/原型引用**：数据库设计 §3.4.1 `edudoc_user`（username/password_hash/auth_source/account_status/last_login_time）、§3.4.2–§3.4.5 角色权限表；概要 §5.2 I01（本地兼容认证）；`04_seed.sql`（已 seed 3 角色 + 20 权限，缺用户）。
- **现状**：`01_schema.sql`~`04_seed.sql` 已手工执行，`edudoc_user` 无数据，无可用登录账号。
- **验收标准**：
  - 新建 `backend/src/main/resources/db_seed/` 目录，种子数据写入该目录；通过启动期 `SeedDataRunner`（或等价）在应用启动时幂等执行（已存在则跳过），BCrypt 哈希由后端 `PasswordEncoder` 运行时生成，不在脚本中硬编码哈希。
  - seed 4 个 LOCAL 账号：`student`/`teacher`/`ops`（`account_status=A`）+ `locked`（`account_status=L`，用于受限流程）；`auth_source='LOCAL'`、`username` 唯一，并通过 `edudoc_user_role` 关联到对应内置角色。
  - 启动后端后 `edudoc_user` 可见 4 个账号，`SELECT` 校验通过；`/api/smoke` 返回 DB 连通。
  - 本次成功执行（不是只落脚本）：以启动后 DB 中可见账号为准。
- **测试**：`SeedDataRunnerTest`（幂等：二次启动不重复插入、账号/角色/状态/哈希字段断言）
- **依赖**：无（schema 已建）
- **状态**：已完成

## A-02 后端 · 登录闭环收尾（错误码/账号状态/last_login/审计）

- **需求/设计/原型引用**：详细设计 §2.2 请求上下文、§2.5 鉴权顺序、§5.1 错误码（40101/40102）；概要 §7.1（令牌短期有效）；需求 I01；契约速查 §2/§3。
- **现状**：`AuthController`/`AuthService`/`LocalAuthProvider`/`JwtService` 已实现（F-03/F-04），未对真实账号联调；`last_login_time` 未更新；登录成功/失败未写 `edudoc_audit_log`。
- **验收标准**：
  - `POST /api/v1/auth/login` 用 A-01 种子账号登录返回 `{token,user}`；用户名/密码错误 → 40101；`account_status∈{L,I,D}` → 40101「账号受限」（不区分账号是否存在，防枚举）。
  - 登录成功更新 `edudoc_user.last_login_time`，并写审计日志（动作=认证，成功与拒绝都记录，`detail_json` 不落口令）。
  - `GET /api/v1/auth/me` 返回 user/roles/permissions；`POST /api/v1/auth/logout` 返回 204。
  - 40101/40102 与错误码表、契约速查对齐。
- **测试**：扩展 `AuthServiceTest`/`LocalAuthProviderTest`（真实 BCrypt 种子账号、锁定账号拒绝、last_login_time 落库、审计写入）
- **依赖**：A-01
- **状态**：已完成

## A-03 后端 · 令牌撤销（logout 黑名单 + 40102）

- **需求/设计/原型引用**：概要 §7.1（令牌短期有效并支持撤销）；详细设计 §5.1 错误码 40102（令牌已撤销）；契约速查 §2。
- **现状**：JWT 为短期无状态签发（F-03），`logout` 仅前端清 token，无服务端撤销，`JwtAuthenticationFilter` 未判 40102。
- **验收标准**：
  - JWT 增加唯一 `jti` 声明；`POST /api/v1/auth/logout` 将当前 token 的 `jti` 写入撤销存储（TTL 与令牌剩余有效期一致），返回 204。
  - `JwtAuthenticationFilter` 在解析后查撤销存储：命中 → 40102；未命中 → 正常建立上下文。
  - 撤销存储用内存实现，对齐既有 `InMemoryIdempotencyStore` 模式（`# ponytail: 单机内存黑名单，多节点部署需换 Redis`）。
- **测试**：扩展 `JwtServiceTest`/`JwtAuthenticationFilterTest`（jti 往返、登出后旧 token → 40102、有效 token → 放行）
- **依赖**：A-02
- **状态**：已完成

- **验收标准**：

- **测试**：`AuthControllerTest`（两占位接口返回 200 + 文本、envelope 结构正确）

## A-05 前端 · 登录页（含密码可见）

- **需求/设计/原型引用**：`04_登录与认证页面设计规范.md`（登录、登录·密码可见：Logo、表单字段、密码显示/隐藏热点、左右分栏尺寸）；详细设计 §4.1 `/login` 路由、§4.2 交互原则（失败保留输入）、§4.3 表单校验；原型认证屏 1–2。
- **现状**：`web/src/pages/Login.tsx` 为居中基础 antd 表单（仅必填校验），缺 Logo/分栏布局、密码可见切换、回跳 query、「忘记密码？」入口、按错误码提示。
- **验收标准**：
  - 登录页含品牌 Logo、用户名、密码（显示/隐藏切换）、登录按钮、「忘记密码？」链接（跳 A-08）。
  - 校验：用户名/密码必填、用户名去首尾空格；失败保留输入。
  - 提交对接 `AuthContext.login`；40101 账号受限 → 跳 A-07 受限页；其它错误按 `ApiError.message` 表单提示。
  - 已登录访问 `/login` → 回跳 `homeOf(roles)`；带 `?redirect=` 登录成功回跳（401 回跳闭环）。
  - 「登录·密码可见」作为同一表单的 `Input.Password` 切换实现，不单独建页。
- **测试**：`web/src/pages/Login.test.tsx`（渲染、校验、提交、错误提示、回跳）
- **依赖**：A-02、F-05（AuthContext）、F-08（antd，已具备）
- **状态**：已完成

## A-10 联调 · 端到端登录闭环

- **需求/设计/原型引用**：详细设计 §4.4 前后端交互（401 保留回跳）、§4.1 路由表；需求 NFR-01（1000 在线）/P-02（3 秒内 95%）。
- **验收标准**：
  - 三角色种子账号 `student`/`teacher`/`ops` 分别登录 → 进入各自工作台 → 登出 → 回登录；登出后旧 token 复用 → 40102 → 跳登录。
  - 未登录访问 `/student` → 40101 → 跳 `/login?redirect=…` → 登录后回跳原页。
  - `locked` 账号登录 → 受限页 → 权限申请占位提示；登录页「忘记密码？」→ 找回密码页 → 占位提示。
  - 令牌过期/本地清除 → 401 → 跳登录并保留回跳。
  - `mvn test` + `pnpm test` 全绿；手工/冒烟跑通三角色链路。
- **测试**：e2e 冒烟清单（组件/单测已分散到 A-05~A-09，此处为端到端联调验证）
- **依赖**：A-02、A-03、A-05、A-06、A-07、A-08、A-09
- **状态**：未开始
