# FormatManualTest · 04 切片浏览器验收手册（D-15 手动全链路）

> 执行者：用户本人。预计 25~40 分钟。每个场景末尾的「□」为勾选记录位；任何一步与预期不符，把界面现象 + 浏览器 Network 响应体 + backend 控制台对应时间段日志贴回即可。
> 口径基准：HTTP e2e 已全绿（见 `FormatTest.md`「e2e 执行记录」），本手册验证的是**同一链路的浏览器表现**（81 屏对照）。

**注意点（必读）**
- `EDUDOC_DB_*`、`EDUDOC_AI_INTERNAL_TOKEN`、`EDUDOC_SOFFICE_BIN`、`EDUDOC_OSS_*` 已用 setx 注入用户环境变量，**新开终端自动生效、无需重复 export**；已开着的旧终端拿不到，务必用新终端。
- `EDUDOC_SOFFICE_BIN` 路径含空格（`C:\Program Files\LibreOffice\...`），若转换报 503「服务器未安装 LibreOffice」，先在该终端执行 `echo %EDUDOC_SOFFICE_BIN%` 确认是完整路径而不是被截断。
- 8080 若被旧实例占用：要么复用旧实例（登录接口能通即可），要么 `taskkill /PID <pid> /F` 后重启。**同一时刻只留一个 backend**，否则 Redis Stream 消费会互相抢消息、日志难追。
- LibreOffice 首次冷启动约 8~10s，之后同一服务进程内会快；转换器已用独立 `-env:UserInstallation` 临时目录，与你手工打开的 LibreOffice 窗口互不冲突（但验收期间建议别开 LibreOffice 主程序）。
- presigned 下载链接 **15 分钟过期**，过期后行内显示「链接已过期，重新转换」属预期。
- 测试账号见上方「测试账号速查」表（M-10 权限反例用 `ops`）。

## 1. 教师端：模板库（原型 teacher 09–14）

**M-01 上传模板并解析**
1. teacher 登录 → 左导航「课程模板」。
2. 选一门有课程的条目 →「新建模板」：命名 `手工验收Web模板`，描述随意 → 确定。
3. 在该模板行点「编辑」→「上传 .docx 并预览解析结果」，选 `docs/test/fixtures/templates/Web开发实战课程设计报告撰写要求.docx` → 点「确认保存为新版本」。

预期（决议①新流程）：上传后**先出蓝色「预览草稿（未保存）：3 条规则」提示条，此时不产生任何版本**（版本下拉禁用，底部按钮变为「确认保存为新版本」/「取消预览」）；点确认后 toast「新版本 vN 已生成」，版本下拉出现 vN（可发布）。规则按族分组（字体/字号/页边距各 1），期望值口语化（如「正文字体 仿宋 / 字号 10.5pt / 页边距+纸张 A4」），「改配置」弹 JSON 编辑；「取消预览」应回到原状态且无任何版本落库（可开版本下拉核对数量未变）。
□ 通过

**M-02 多形态模板语料**
上传 `C语言课程设计报告格式.docx`（新建模板 `手工验收C语言模板`）。

预期：规则数 **10**；标题1 显示黑体、标题2 Arial+1.73 倍行距；正文行距显示「未声明/不校验」（atLeast 无值不产规则的口径，勿当成 bug）。
□ 通过

**M-03 编辑规则与保存闸**
进入某版本「编辑规则」，把字号期望改成 `0` 或清空 → 保存。

预期：前端校验即时红字拦截（保存根本发不出去）；即使绕过前端，后端仍 40001 拒绝（RuleConfig 单源不变量）。改回合法值保存成功。
□ 通过

**M-04 发布确认 + 历史版本不受影响（UT-13）**
1. 对 M-01 版本点「发布」→ 确认 Modal 展示版本/范围/说明与「发布后学生端按此版本校验」提示 → 确认。
2. 发布后再上传一个新版本（随便再传同一文件）并再次发布。
3. 回到版本列表查看第一版详情。

预期：当前生效版本为 v2；v1 的规则与状态原样可查（历史版本只读、不随新发布漂移）。

4. （二轮新增）**在已发布版本上编辑另存**：版本下拉选已发布的 v1 → 页脚点「基于此版本编辑另存新版本」→ 出现黄色「正在基于已发布 v1 编辑副本」提示条，规则可改（如把字号 10.5 改成 14）→ 点「另存为新版本」。

预期：toast「已另存为新版本 v3（未发布，不影响 v1）」；版本列表出现 v3 未发布（可编辑可发布），v1/v2 均保持发布态；改一条非法值（如 pt=0）点另存 → 红字拦截且**不会**产生新版本；「退出编辑（不保存）」回到只读回显。
□ 通过

**M-07 上传错题集 + 校验面板（核心场景）**
1. 文档列表「上传」→ 选 `docs/test/fixtures/mutated/Web开发实战课程设计报告撰写要求.mutated.docx`，课程选 M-04 发布的同课程，类型 报告。
2. 打开该文档预览 → 右侧「格式校验」面板 → 点「开始校验」。

预期（逐项核对）：
- 按钮进入 loading，面板出现排队/进行中态，约 10~30s 内出结论横幅 **红色「未通过」**，文案含「共 52 个问题，阻断 1 个」量级（±少量随模板版本，阻断必须=1）。
- 问题清单按严重级着色，MARGIN 行标 BLOCKER；行首复选框**只有可自动修复行可勾选**。
- 点任一「定位到正文」：预览正文滚动到对应段落并**黄色高亮具体区间**（不是整段）；个别定位失败时退化为跳页并给提示，属已声明的近似口径。
- 刷新页面重进该文档：面板恢复上次校验结果（localStorage checkId 续查）。
□ 通过

**M-08 一键修复 → 复审**
1. 勾选前 4 条可修复问题 →「一键修复」。
2. 修复弹窗出现三段影响面：本次将修复（4）/未勾选的可修复/不可修复+指引 → 确认。

预期：提示修复成功并生成**新版本（版本号 +1，文档列表「版本」列可见 v1→v2）**；面板自动重查，结论横幅变 **绿色「通过」**，总数降为 **48、阻断 0**。

3. 文档列表该行点「版本」链接（决议④新增）。

预期：Drawer 打开，**v2（编辑/修复 · 一键修复 · 当前标）在 v1（上传）之上**；v2 行有「下载」（签名链接打开=修复后的 docx，可正常打开）；说明文案含「回滚随协作与版本切片」。编辑模板弹窗内的「版本历史」折叠区是**模板**版本，与这里文档版本互不相干。

**M-10 反例组**（每小项 1 分钟）

## 3. 已知边界（不算 bug，验收时勿纠结）

- **格式视图（v3：转换引擎真渲染 + 页内字节流内嵌）**：docx 切换后自动走 LibreOffice 转换出 PDF，再经后端字节流端点（带登录态）在页内直接显示——**不是下载**，不依赖 OSS 域策略/CORS，与下载产物同引擎版式 100%。首次约 8~15s 显示「正在用转换引擎生成版式预览」，之后复用产物秒开；修复/编辑出新版本后旧产物自动作废重转；超 20MB 提示改走下载。PDF 课件原件同样页内显示。转换失败显示失败码与原因（如 ENCRYPTED）。段落→块定位仍是文本视图估算，精确映射随协作切片。
- **OPS 无转换入口为当前口径**（seed 权限矩阵 OPS 无 FORMAT_CONVERT，且涉及文档可见 ACL），待治理切片统一开放，非缺陷。
- JavaEE 等 PDF 转换件的页边距/字体解析不可信（语料评估已记录），**不要**拿它当模板上传验收解析质量。
- 题注（CAPTION）族错题样本本期无真语料可注入（机制限制），校验面板里题注类问题以模板真实使用为准。
- 校验/修复/转换写接口都带 Idempotency-Key（前端自动生成），双击/重放不会重复建任务。
- presigned 直链 15 分钟过期；过期表现=「链接已过期，重新转换」，历史抽屉同理。
- 电脑睡眠唤醒后 worker 对 Redis 可能出现短暂超时重试，任务会晚几十秒被消费，非功能缺陷（可看 backend 日志 `Redis command timed out` 判断）。
