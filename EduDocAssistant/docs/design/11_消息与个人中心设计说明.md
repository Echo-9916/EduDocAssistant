## 一、范围

- **做**：站内信箱（列表/已读/偏好）、四类消息生产者、个人中心资料与安全项、会话列表与下线、登录记录。
- **不做**：邮件/企业微信等外部投递（依赖 I06 邮件网关，未定）；`edudoc_security_incident` 等运维安全事件表（切片 4）；实时协同（本期不建 gateway）。

## 二、数据模型（三张新表 + 一列）

### 2.1 `edudoc_notification` 站内信箱

| 列 | 类型 | 说明 |
| --- | --- | --- |
| id | RAW(16) | 主键，SYS_GUID |
| recipient_id | RAW(16) | FK `edudoc_user`，收件人；查询主入口 |
| notif_type | VARCHAR2(20) | CHECK：`COURSE`/`SUBMISSION`/`FEEDBACK`/`FORMAT`/`PERMISSION`/`ALERT`/`APPROVAL`/`SYSTEM`（与门面 `mock/domain/messages.ts` 的八类逐字对齐，避免前端二次映射） |
| title | VARCHAR2(200) | 标题 |
| body | VARCHAR2(1000) | 正文 |
| resource_type | VARCHAR2(20) | 关联对象类型，可空 |
| resource_ref | VARCHAR2(200) | 关联对象标识（id 或名称），供「前往处理」 |
| actor_id | RAW(16) | 触发人，可空（系统消息为空） |
| dedup_key | VARCHAR2(64) | 幂等键：同一事件重投不产生第二封信（见 4.3） |
| read_at | TIMESTAMP(6) WITH TIME ZONE | 已读时间，空即未读 |
| create_time / update_time | TIMESTAMP(6) WITH TIME ZONE | 三公共列，配 `trg_notification_bu` |

约束与索引：`uk_notification_1(recipient_id, dedup_key)`（投递幂等）；`ix_notification_recipient(recipient_id, read_at, create_time)`；`ix_notification_type(notif_type, create_time)`。

### 2.2 `edudoc_notification_preference`

`(id, user_id FK, notif_type, channel, enabled CHAR(1) Y/N, create_time, update_time)`，
`uk_notif_pref_1(user_id, notif_type, channel)`；`channel` 本期只有 `INBOX`，预留 `EMAIL` 值不实现。

### 2.3 `edudoc_access_policy`（访问策略，屏 13 用；同批建，实现在切片 4）

`(id, policy_key UK, policy_json, description, updated_by, create_time, update_time)`。
本切片只用它的「会话安全」两项（并发会话上限、空闲超时）作为会话列表口径来源，其余留切片 4。

### 2.4 `edudoc_user.mfa_enabled CHAR(1) DEFAULT 'N' NOT NULL CHECK (Y/N)`

运维强制 `Y`：在应用层校验（OPS 角色不允许关），不加数据库触发器，避免把策略写进 DDL。

> 会话与登录记录**不建表**：会话在 Redis（`UserPrincipal` 令牌撤销已有 `TokenRevocationStore` 先例），
> 登录记录读 `edudoc_audit_log` 的 `AUTH` 动作 + `edudoc_user.last_login_time`，与库设计文档
> 「Redis 不作为业务事实来源」一致。这样屏 27 的会话表与登录记录不需要新结构。

## 三、端点契约（8 个）

| 方法 路径 | 权限 | 说明 |
| --- | --- | --- |
| GET `/api/v1/messages?type&read&page&pageSize` | 认证即可（本人） | `PageResult<MessageView{id,type,title,body,resourceType,resourceRef,actorName,createdAt,read}>`；未读数以 `unreadCount` 单独返回，避免前端拉全量 |
| PATCH `/api/v1/messages:read` `{ids:[…], read:bool}` | 本人 | 批量已读；空数组 40001；只允许改自己的行（越权 id 静默忽略并在响应回 `updated` 数，不泄露他人消息存在性） |
| GET `/api/v1/me/profile` · PUT `/api/v1/me/profile` | 本人 | 可改：姓名、院系/组织、邮箱、手机；**只读**：学号/工号、角色、课程/值班组（统一身份认证与排班同步） |
| GET `/api/v1/me/security` · PUT `/api/v1/me/security` | 本人 | `twoFactor`、`sensitiveVerify`、`newDeviceAlert` + 通知偏好；OPS 关双因素 → 40301 |
| POST `/api/v1/me/password` `{oldPassword,newPassword,confirmPassword}` | 本人 + 二次验证 | 改密后立即撤销其余会话（复用 `TokenRevocationStore`），返回需在登录页重登 |
| GET `/api/v1/me/sessions` · DELETE `/api/v1/me/sessions/{sessionId}` | 本人 | 会话来自 Redis；下线写审计；当前会话不可下线（40901） |
| GET `/api/v1/me/login-records?range` | 本人 | 读 `audit_log` 的 `AUTH`，字段含设备/IP/位置/结果；异地标记由「与最近一次成功登录的城市不同」现算 |

## 四、生产者与异步链路

### 4.1 四类生产者（本切片必须打通，否则消息中心是空壳）

| 事件 | 来源 | notif_type | 收件人 | 触发点 |
| --- | --- | --- | --- | --- |
| 作业提交 | 切片 1 `StudentCourseworkService#submit` | `SUBMISSION` | 该课程 TEACHER 成员 | 提交事务内 Outbox 发 `NOTIFICATION_REQUESTED` |
| 批改反馈 | 切片 1 `#grade` | `FEEDBACK` | 提交学生 | 同上（补上切片 1 遗留债 1「提醒只出名单不投递」） |
| 格式异常 | `FormatCheckWorker` 结论 BLOCKER>0 | `FORMAT` | 文档 owner | Worker 侧发事件（不改校验主链路语义） |
| 作业临近截止 | 定时扫描（每小时，`due_time` 未来 48h 内且学生未交） | `SUBMISSION` | 未交学生 | 新增 `@Scheduled` 扫描，走同一事件类型 |

### 4.2 异步链路的三处齐动（缺一处事件直接 FAILED）

1. 事件类型 `NOTIFICATION_REQUESTED` 进 `edudoc_outbox_event`；
2. `application.yml` 的 `edudoc.outbox.stream-keys` 登记 `NOTIFICATION_REQUESTED: edudoc:stream:notification`；
3. 新增 `NotificationWorker`（沿用 `DocumentParseWorker` 骨架：`MKSTREAM` 幂等建组、`pid` consumer 名、`XACK`）。
   消费时按 2.2 的偏好过滤（关掉某类就不落信箱），一次事件可产生多行（多收件人）。

### 4.3 幂等与重复投递

- `dedup_key = {eventType}:{aggregateRef}:{recipientId}`，配合 `uk_notification_1`；
  Outbox 重投或调度器重复扫描都不会产生第二封信——这是「重放即原结果」在信箱上的等价实现，
  与待确认 A5 的全局幂等语义分开处理。
- 临近截止扫描每天最多一封：`dedup_key` 含日期。

## 五、验收口径

- 三端消息中心页头去掉「演示数据」标记（`live`），`operations/messages` 的告警类仍是 mock（`mixedNote`），因为告警生产者属切片 4。
- 端到端可演示且不留假象：教师发布 → 学生提交 → **教师当场收到提交消息** → 教师批改 → **学生当场收到反馈消息且点开能跳到作业**；关掉某类偏好后该类不再出现。
- 负例必须有：越权改他人消息已读不生效；OPS 关双因素被拒；改密后其他会话不可用；`messages:read` 空数组 40001；重复事件不产生第二封信（查 `uk_notification_1` 冲突计数）。
- 回归门：`mvn test` 全绿（新增 notification 用例）、`tsc` 0 错误、`vitest` 全绿、`smoke-facade.mjs` 24 页 0 失败且 LIVE 断言名单加入三端消息页与个人中心。

## 六、要你拍板的（已同步进 `docs/tasks/06-待确认清单.md`）

1. **消息是否要「未读数进工作台角标」**：本设计只给 `unreadCount` 接口，不预聚合；要角标就加一个 `/messages/unread-count`（便宜）。
2. **临近截止提醒的提前量**：默认 48 小时、每天最多一封；改口径只需换常量。
3. **A4 口径**：若你选「格式未过禁止提交」，则格式异常生产者从「通知」升级为「提交前置校验」，本切片 4.1 第 3 行改写。
4. **运维告警生产者**（`ALERT`：解析积压、存储超限）现在做还是留切片 4：现在做要读 Redis 队列长度与 OSS 用量，约多一天。
