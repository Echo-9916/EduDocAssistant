### 1.2 系统概述

校园智能文档助手由三部分组成：

| 组成部分 | 作用 |
| --- | --- |
| Web 界面 | 学生、教师、运维通过浏览器使用系统 |
| 业务服务 | 处理登录、权限、文档、模板、作业、批改、协作、审计等业务 |
| 智能处理服务 | 提供摘要、要点、问答、润色、向量化与格式转换能力 |

系统还依赖数据库、缓存、对象存储和模型服务。Docker 部署会把 Web、业务服务、智能处理服务和数据库/缓存统一编排；对象存储与模型服务作为外部依赖，通过配置接入。

## 2 安装环境

### 2.1 硬件与系统要求

| 项目 | 建议 |
| --- | --- |
| 操作系统 | Windows 10/11、Linux 或 macOS，支持 Docker Desktop / Docker Engine |
| CPU | 4 核及以上 |
| 内存 | 6GB 及以上（Oracle 首次初始化占用较高） |
| 磁盘 | 15GB 及以上可用空间 |
| 网络 | 可访问镜像仓库、依赖仓库；可访问对象存储与模型服务 |

### 2.2 软件依赖

| 软件 | 要求 |
| --- | --- |
| Docker | Docker Desktop 或 Docker Engine |
| Docker Compose | Compose v2（使用 `docker compose` 命令） |
| 浏览器 | Chrome / Edge / Safari 等现代桌面浏览器 |

首次拉取 Oracle 镜像需要登录 Oracle 容器仓库（免费账号）：

```bash
docker login container-registry.oracle.com
```

如果本机已有 `container-registry.oracle.com/database/free:latest` 镜像，可跳过此步。

### 2.3 网络与端口

| 端口 | 用途 | 是否对外 |
| --- | --- | --- |
| `8088` | Web 访问入口（Nginx） | 是 |
| `8080` | 业务服务 | 否，容器内部 |
| `8000` | 智能处理服务 | 否，容器内部 |
| `1521` | 数据库 | 否，容器内部 |
| `6379` | 缓存/任务队列 | 否，容器内部 |

如 `8088` 被占用，可在 `.env` 中修改 `EDUDOC_WEB_PORT`。

### 2.4 外部依赖

| 依赖 | 用途 | 必须配置 |
| --- | --- | --- |
| 阿里云 OSS 私有 Bucket | 存放文档、作业附件、文档图片 | 上传/附件/图片功能需要 |
| 硅基流动模型服务 | 摘要、要点、问答、润色 | 智能处理功能需要 |

未配置对象存储时系统仍可启动，但上传、附件、图片接口会提示服务不可用；未配置模型密钥时智能处理会提示失败。

## 3 安装前准备

### 3.1 获取代码

```bash
git clone <仓库地址>
cd SoftwareProjectImpl
```

### 3.2 准备配置文件

进入部署目录（后续命令默认在此目录执行）：

```bash
cd EduDocAssistant/deploy
```

```bash
cp .env.example .env
```

按实际情况填写 `.env`：

| 变量 | 说明 |
| --- | --- |
| `EDUDOC_WEB_PORT` | Web 对外端口，默认 `8088` |
| `EDUDOC_ORACLE_PWD` | 数据库管理员密码；首次启动后不要随意修改 |
| `EDUDOC_DB_USERNAME` / `EDUDOC_DB_PASSWORD` | 业务数据库账号，默认 `user_cidas` / `cidas123` |
| `EDUDOC_JWT_SECRET` | 登录令牌签名密钥；留空由启动脚本生成 |
| `EDUDOC_AI_INTERNAL_TOKEN` | 业务服务与智能处理服务的共享令牌；留空由启动脚本生成 |
| `SILICONFLOW_API_KEY` | 模型服务密钥 |
| `EDUDOC_OSS_*` | 对象存储地址、地域、Bucket、访问密钥、直传角色 |
| `EDUDOC_INSTALL_CONVERT` | 是否安装格式转换组件，默认 `true` |

> `.env` 含敏感信息，不要提交到版本库；仓库已忽略该文件。

### 3.3 准备对象存储

如果使用浏览器上传文档，需要在 OSS Bucket 配置跨域规则，至少允许：

- 来源：`http://<服务器地址>:8088`（或实际域名/端口）
- 方法：`GET, PUT, POST, HEAD`
- 请求头：`*`
- 暴露头：`ETag`

否则浏览器上传会因跨域失败。

### 3.4 检查端口与磁盘

```bash
docker compose version
docker ps
```

确认 Docker 正常运行，`8088` 未被占用，磁盘可用空间充足。

## 4 安装步骤

### 4.1 一键安装（推荐）

Windows PowerShell：

```powershell
.\deploy\start.ps1
```

Linux / macOS / Git Bash：

```bash
chmod +x start.sh
./start.sh
```

脚本会：

1. 检查 Docker 与 Compose；
2. 复制 `.env.example` 为 `.env`（不存在时）；
3. 自动生成 JWT 密钥与共享令牌（为空时）；
4. 构建镜像并启动全部容器；
5. 等待 Web 就绪，打印访问地址与演示账号。

首次启动需要初始化数据库，通常 5–10 分钟；后续启动约 1 分钟。

### 4.2 手动安装（等价命令）

```bash
docker compose --env-file .env up -d --build
```

只构建某个服务：

```bash
docker compose --env-file .env build backend
docker compose --env-file .env build web
docker compose --env-file .env build ai-service
```

### 4.3 容器说明

| 服务 | 作用 | 启动方式 |
| --- | --- | --- |
| `oracle` | 数据库 | 常驻 |
| `db-init` | 首次建表、建用户、初始化数据 | 一次性，成功后退出 |
| `redis` | 缓存与任务队列 | 常驻 |
| `ai-service` | 智能处理 | 常驻 |
| `backend` | 业务服务 | 常驻 |
| `web` | 前端与反向代理 | 常驻，对外 `8088` |

> `db-init` 显示 `Exited (0)` 是正常现象；它检测到数据库已初始化后会跳过并退出。

## 5 初始化与验证

### 5.1 初始化内容

首次启动时，`db-init` 会：

1. 等待数据库与业务库就绪；
2. 创建业务表空间与数据库账号；
3. 执行建表、索引、触发器与基础种子数据；
4. 检测到业务表已存在时跳过，保证重复启动幂等。

随后业务服务会写入演示账号与演示课程数据（若尚未存在）。

### 5.2 验证服务状态

```bash
docker compose --env-file .env ps
```

预期：`oracle`、`redis`、`ai-service`、`backend`、`web` 均为 `healthy`；`db-init` 为 `Exited (0)`。

### 5.3 验证 Web 与登录

打开：

```text
http://<服务器地址>:8088
```

使用演示账号登录：

| 角色 | 账号 | 密码 |
| --- | --- | --- |
| 教师 | `teacher` | `Cidas@123` |
| 学生 | `student` | `Cidas@123` |
| 运维 | `ops` | `Cidas@123` |

也可以直接验证登录接口：

```bash
curl -s -X POST http://localhost:8088/api/v1/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"teacher","password":"Cidas@123"}'
```

返回 `"code":200` 即表示 Web → 业务服务 → 数据库链路正常。

### 5.4 验证智能处理

- 登录后上传一份 Word 文档，等待状态为「就绪」；
- 打开文档预览，尝试「生成摘要」或「文档问答」；
- 若提示失败，检查 `.env` 中的模型密钥与网络。

### 5.5 验证上传与对象存储

- 在「我的文档」上传一份 Word/PDF；
- 若上传失败，检查 OSS 凭据、Bucket、跨域规则与网络。

## 6 升级与回滚

### 6.1 升级应用

数据卷会保留数据库与缓存数据。

```bash
git pull
docker compose --env-file .env up -d --build
```

仅升级应用服务：

```bash
docker compose --env-file .env up -d --build backend web ai-service
```

### 6.2 回滚应用

```bash
git checkout <上一个可用版本>
docker compose --env-file .env up -d --build backend web ai-service
```

如果数据库结构也发生变化，需要先恢复数据库备份或使用对应版本的初始化脚本；不建议直接回滚到不兼容的数据库结构。

### 6.3 备份与恢复

数据卷：

- `edudoc_oracle_data`：数据库数据文件；
- `edudoc_redis_data`：缓存与任务队列数据。

备份前建议先停止业务写入：

```bash
./stop.sh
```

备份数据卷可以使用 Docker 卷备份工具或直接复制卷目录；恢复时保持卷名一致后再启动。

## 7 卸载

### 7.1 停止并保留数据

```bash
./stop.sh
# 或
docker compose --env-file .env down
```

### 7.2 停止并删除数据

```bash
docker compose --env-file .env down -v
```

> 该命令会删除数据库与缓存数据，下次启动会重新初始化，请确认不再需要现有数据。

### 7.3 删除镜像（可选）

```bash
docker image rm edudoc-backend edudoc-web edudoc-ai-service
```

Oracle 镜像较大，如不再使用可单独删除。

## 8 故障处理

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| Oracle 启动很慢 / `db-init` 一直等待 | 首次建库正常；内存不足 | 查看 `docker compose logs oracle`；关闭其他占用内存的容器；等待 5–10 分钟 |
| `db-init` 失败 | 数据库未就绪、建表脚本报错、卷中已有半初始化数据 | 查看 `docker compose logs db-init`；必要时 `down -v` 后重来 |
| 向量索引创建失败（日志提示 `ORA-51962`） | 容器默认向量内存为 0 | 不影响演示与普通检索；需要索引时按 [Docker 部署说明](../EduDocAssistant/deploy/README.md) 配置向量内存后补建 |
| Web 打不开 | 端口被占用、容器未启动、Nginx 未就绪 | 检查 `docker compose ps`；修改 `EDUDOC_WEB_PORT`；查看 `docker compose logs web` |
| 登录失败 | 数据库未初始化、账号密码错误、账号被冻结 | 查看 `db-init` 日志；确认账号状态；联系运维解冻 |
| 上传失败 | OSS 未配置、跨域规则缺失、文件超限 | 检查 `.env` 的 OSS 配置与 Bucket 跨域；确认文件 ≤20MB |
| 智能处理失败 | 模型密钥未配置、网络不可达、文档未就绪 | 检查模型密钥与网络；确认文档状态为「就绪」 |
| 后端启动失败 | 配置缺失、数据库连接失败 | 查看 `docker compose logs backend`；检查 `EDUDOC_DB_URL` 与数据库状态 |
| 修改数据库密码后无法连接 | 数据库卷已存在，旧密码仍生效 | 使用旧密码登录后修改，或按重建数据卷流程处理 |

常用排查命令：

```bash
docker compose --env-file .env ps
docker compose --env-file .env logs -f
docker compose --env-file .env logs -f db-init
docker compose --env-file .env logs -f backend
```
